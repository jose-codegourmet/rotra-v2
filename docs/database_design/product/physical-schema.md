# Physical schema (drafted)

**Last verified:** 2026-10-31.

**Status:** Draft Prisma models and **unapplied** migration SQL in `packages/db/prisma/`. Each migration
needs human sign-off before it touches any database ([coding conventions §13](../../coding-conventions.md#13-database-later-epic)).
Decision gates #243–#248 are still open; every choice below that depends on them is marked.

Common to every table: UUID keys (`uuid(7)` generated by the client) unless noted, `timestamptz(6)`
instants, `revision bigint default 1` on mutable records, money as integer minor units plus a
`char(3)` currency. All application tables have `REVOKE ALL … FROM anon, authenticated`: they are read
only through server Route Handlers and services, never through the Supabase Data API.

## Group B · licenses, configuration, audit (F07.10 · `20261031000200`)

| Table | Keys and uniques | Checks and triggers | Delete behavior |
|---|---|---|---|
| `club_license_terms` | PK `id`; unique `source_command_id`, `payment_reference`, `(club_id, id)`; index `(club_id, starts_at desc)`, `activated_by_admin_id` | start < end; amount ≥ 0; `pricing_at_activation = free` ⇒ amount 0 and no `paid_on`; paid ⇒ amount > 0 and `paid_on`; **append-only** trigger | `RESTRICT` to club and admin |
| `club_entitlements` | PK/FK `club_id`; composite FKs `(club_id, effective_term_id)` → terms, `(club_id, current_expiry_cycle_id)` → cycles | term and access end both set or both null | `RESTRICT` |
| `club_expiry_cycles` | PK `id`; unique `(club_id, id)`; partial unique `club_id WHERE state = 'running'`; index `(state, delete_public_pages_after, id)` for cleanup, `(club_id, expired_at desc)` | deadline > expiry; `cancelled` ⇔ `cancelled_at`; cancellation term only on cancelled; composite FK to the cancelling term | `RESTRICT` |
| `club_name_change_requests` | PK `id`; unique `source_command_id`; partial unique `club_id WHERE state = 'pending'`; index `(club_id, requested_at desc)`, `(state, requested_at)` | non-blank name/key; approved/rejected ⇒ reviewer + time | `RESTRICT` |
| `admin_audit_events` | PK `id`; unique `source_command_id`; index `(actor_admin_id, occurred_at desc)`, `(target_type, target_id, occurred_at desc)` | **append-only** trigger; metadata is redacted | `RESTRICT` to admin |
| `feature_flags` | PK `key`; unique `name varchar(50)` | key `^[a-z][a-z0-9_]{2,39}$`; key-immutable trigger; catalog starts empty | `RESTRICT` to admins |
| `ranking_policy_versions` | PK `id`; unique `version`; index `effective_at desc` | each weight 0–10000, sum 10000; threshold 1–40; **append-only** trigger; seeded 7000/3000/10 | `RESTRICT` to admin |

- Changing a club's price never touches `club_license_terms`: each term keeps the amount and pricing it
  was recorded with, and the table rejects updates.
- Renewal cancels the exact running cycle (`cancellation_term_id`); a later expiry inserts a new
  `running` cycle, so a stale deletion job can never act on a renewed club. Cycle states
  `running · cancelled · completed` are a proposal pending #245/#248.
- `ranking_policy_versions` has no status, job or result columns: saving settings records configuration,
  never a completed recalculation. `algorithm_version` is `unapproved` until #247.

## Group C · player identity, contacts, claims, RTR IDs (F07.11 · `20261031000300`)

| Table | Keys and uniques | Checks and triggers | Delete behavior |
|---|---|---|---|
| `players` | PK `id` (never an auth subject); index `full_name` | non-blank name; experience ≥ 0 and recorded together; details carry a version | Referenced with `RESTRICT` everywhere |
| `player_private_contacts` | PK/FK `player_id`; unique `phone_e164`, unique non-null `email` | E.164 phone; email trimmed + lowercase | `RESTRICT` |
| `player_accounts` | PK/FK `player_id`; unique `(auth_provider, auth_subject)` | deferred constraint trigger: a claimed account needs phone **and** email at commit | `RESTRICT`; no FK to `auth.users` |
| `player_social_links` | PK `id`; unique `(player_id, provider)` | `https://` URL | `RESTRICT` |
| `player_claim_links` | PK `id`; unique `token_digest` (32-byte SHA-256); partial unique `player_id WHERE state = 'active'`; index `(player_id, issued_at desc)`, `(issuing_club_id, issued_at desc)` | expiry > issue; `active · consumed · revoked` each match their timestamps | `RESTRICT` |
| `player_id_counters` | PK `(location_code_id, sync_date)` | `last_sequence > 0`; advanced only by `rotra_next_player_sequence` (one atomic upsert) | `RESTRICT` |
| `player_id_allocations` | PK/FK `player_id`; unique `rtr_id`, `(location_code_id, sync_date, sequence)`; FK to its counter | RTR format `RTR-CC-CCC-MMDDYY-NNNN+` with the frozen codes; **append-only** trigger | `RESTRICT` |

- **No auth cascade.** Account mappings store the provider subject as data, not as an FK into Supabase's
  managed `auth` schema, so disabling or deleting an auth user never removes a player or their history.
- **One phone identity, one permanent ID.** The unique phone and the `player_id` PK on allocations make
  a concurrent second allocation fail; the loser retries from identity resolution. Sequences come from
  the counter upsert, never `MAX(sequence) + 1`. `@rotra/db/player/rtr-id` formats IDs and calls the
  function; the sync-day timezone (`Asia/Manila`) is a proposal pending #244.
- **Claims** store only a token digest. One active link per player (reissue revokes) is a proposal
  pending #244. Unclaimed identities have no `player_accounts` row.
- Private contacts and claim digests are never selected into public projections; public reads use
  explicit allowlists (F07.20 service boundary).

## Group H (part) · contact-change requests (F07.18 · `20261031000400`)

`player_contact_change_requests`: PK `id`; unique `source_command_id` (submit idempotency) and
`provider_operation_ref` (set on approval, kept by every retry); indexes `(player_id, requested_at desc)`,
`(status, requested_at)`, `(field, proposed_value)`. All admin and player FKs are `RESTRICT`.

| Rule | Enforcement |
|---|---|
| Approved ≠ applied | Only `status = 'applied'` has `applied_at`, and it also needs `provider_applied_at` (stage 1: provider login changed; stage 2: private contact row matches). `approved`, `applying` and `failed` are all *not applied*. |
| Approval evidence | Every state past `pending` except `rejected` needs reviewer, `reviewed_at`, `approved_at` and `provider_operation_ref`; `rejected` needs reviewer and `rejected_at` and no approval. |
| No conflicting accepted updates | Partial uniques: one open `app` request per player; one in-flight (`approved · applying · failed`) request per player; one in-flight request per `(field, proposed_value)` across all players, which reserves the identifier before the provider call. |
| Retries | `failed` keeps its `provider_operation_ref`; `application_attempts`/`last_attempt_at` record retries; `failure_code` is a short code, never a contact value. |
| Finality | Trigger rejects any update or delete once `applied` or `rejected`. |
| Privacy | Proposed/original values are private normalized contacts. The table has no grants for `anon`/`authenticated`; services expose a request only to its player and the platform owner. No password or contact-proof material is stored. |

Approval and application commands also write `admin_audit_events` with redacted metadata (no contact
values). The player's UUID and RTR ID never change. Auth-provider mutation is not part of this ticket.

## Runtime access (F07.20)

- Apps reach these tables only through `@rotra/db` services behind `handleAccountRequest` /
  `handlePublicRead` ([architecture §8](../../architecture.md#8-auth-target-not-built)). The Prisma
  runtime connection is server-only and does not carry an end-user JWT, so RLS is **not** claimed to
  scope it; authorization happens in the service layer on every request.
- Every table above revokes `anon`/`authenticated`; nothing is reachable through the Supabase Data API.
  The runtime role's own grants and the selected project's advisors must still be checked before any
  migration is applied (#243).

## Group D · venues, club players, Queue Sessions, roster, assessments (F07.13 · `20261031000500`)

Offline-creatable records (`club_players`, `queue_sessions`, `session_courts`, `session_players`,
`session_waitlist`, `session_join_requests`, `club_assessments`) take client-generated UUIDs (no
default). Every child carries `club_id` and reaches its parent through a **composite FK**, so a valid
UUID from another club or session is rejected.

| Table | Keys and uniques | Checks and triggers | Scoped FKs |
|---|---|---|---|
| `club_players` | PK `id`; unique `(club_id, id)`, `(club_id, player_id)` (nulls distinct, so guests repeat); index `(club_id, display_name, id)` | non-blank name | club; optional player |
| `club_player_private_inputs` | PK/FK `club_player_id`; unique `(club_id, club_player_id)`; index `(state, captured_at)`, `phone_e164` | E.164 / lowercase email; `resolved` ⇔ resolved player + time | `(club_id, club_player_id)` |
| `club_venues` | PK `id`; unique `(club_id, id)`, expression unique `(club_id, lower(name))` | fees null or ≥ 0 | club |
| `queue_sessions` | PK `id`; unique `(club_id, id)`, `public_slug`, `source_command_id`; partial unique `club_id WHERE state IN (active, finalizing)`; index `(club_id, scheduled_start_at desc, id)` | end > start; minimum ≥ 0; players per court 2–20; invalid ⇒ reason; completed ⇔ `finalized_at`; **exclusion** no overlapping non-invalid sessions per club (`btree_gist`) | `(club_id, venue_id)`, `(club_id, start_license_term_id)` |
| `club_session_reservations` | PK `club_id`; unique `session_id` | — | `(club_id, session_id)` |
| `session_courts` | PK `id`; unique `(club_id, session_id, id)`; partial unique `(session_id, label) WHERE removed_at IS NULL` | non-blank label; soft removal | `(club_id, session_id)` |
| `session_players` | PK `id`; unique `(club_id, session_id, id)`, `(session_id, club_player_id)`, `(session_id, player_id_at_entry)`; index `(session_id, present, id)` | release time ⇔ reason; locked ⇒ level + assessment, not released; **level-lock** trigger; **no delete** trigger | `(club_id, session_id)`, `(club_id, club_player_id)`, `(club_id, session_id, id, assessment_id)` → the entry's own assessment |
| `session_waitlist` | PK `id`; unique `(session_id, club_player_id)`; order index `(session_id, demoted_at desc, demoted_confirmed_at, added_at, id)` | demotion time ⇔ demoted slot time | `(club_id, session_id)`, `(club_id, club_player_id)` |
| `session_join_requests` | PK `id`; index `(session_id, status, requested_at)` | pending ⇔ no decision time; confirmed ⇒ club player | `(club_id, session_id)`, `(club_id, club_player_id)` |
| `club_assessments` | PK `id`; unique `source_operation_id`, `(club_id, club_player_id, id)`, `(club_id, session_id, session_player_id, id)`; rank indexes per ranking.md | actor = owning club; **append-only** trigger | `(club_id, club_player_id)`, `(club_id, session_id)`, `(club_id, session_id, session_player_id)`, `(club_id, club_player_id, supersedes_id)` |

**Roster identity (proposal, #245).** One `session_players` row per (session, club player) for the
session's lifetime. Demotion and preparation removal set `released_at` + `release_reason`; rows are
never deleted (trigger) and all references are `RESTRICT`, so paid marks and assessments keyed on the
entry are never cascaded. Regaining a slot reactivates the same row. Waitlist rows are deleted on Give
slot.

**Waitlist order (proposal, #245).** Demoted entries first (latest demotion batch at the front), each
batch in original slot order (`demoted_confirmed_at`); then everyone else by `added_at`; `id` breaks
ties. Historical timestamps are never rewritten and there is no position column.

**Roster/assessment cycle.** No fake history: insert the roster row with `assessment_id` null, insert
the assessment that references that entry, then point the entry at it, in one transaction. The
composite FK only accepts an assessment for this exact club, session and entry.

| Rule | Database | Transaction |
|---|---|---|
| Schedule clash | exclusion constraint | names the clashing session and whether it is a venue or time clash; series inserts only free dates |
| Capacity | — (slots are derived) | lock the session row; count live entries against `players_per_court × live courts` |
| One active session | partial unique on active/finalizing | offline-start reservation (later ticket) |
| Locked levels | level-lock trigger + locked check | set at start / late entry |
| Visitor ownership | — | pending #248; no public write here |

`decided_by_device_id`, `club_assessments.device_id` and `source_operation_id` gain FKs to `devices` /
`sync_operations` with the sync schema (F07.14).

## Queue preparation services (F07.23)

`@rotra/db/queue/session-preparation` and `@rotra/db/queue/session-roster` implement the Q-SETUP,
Q-PREPARE and Q-ROSTER commands for a verified `ClubContext`. No Route Handlers call them yet.

| Rule | How |
|---|---|
| Serialization | Every command locks the session row (`SELECT … FOR UPDATE`) and bumps `revision`; edits and start take the expected revision (`conflict` on mismatch) |
| Capacity | Admission counts live entries against `players_per_court × live courts` under the lock, so concurrent admissions cannot overfill; Give slot may go over budget and records `over_budget_at` |
| Retries | Create/series: IDs derived from `commandId`. Admissions: `operationId` is the assessment's `source_operation_id`, and the waitlist/entry/club-player IDs derive from it. A retry returns the first result |
| Budget change | Prepared save releases entries beyond the new capacity (`demoted`), adds them to the waitlist with demotion evidence (front, in slot order); a larger budget fills from waitlist order. Active sessions never rebalance |
| Regaining a slot | Reactivates the player's released entry, so paid marks and assessments keyed on it stay attached |
| Levels | Each admission or level change appends a `club_assessments` row and selects it; start refuses any entry without a level and locks all levels; a late entry locks on insert; the trigger rejects later changes |
| Schedule | Clash messages come from the shared `sessionOccurrences` rule (`@rotra/data`); the exclusion constraint is the race backstop. Series insert only free dates |
| License | Create, edit and start need a current entitlement; start records `start_license_term_id`. An active session started under a term keeps working after expiry (completion exception) |
| Minimum | Recomputed with the shared `estimateMinimum` rule while prepared and calculated; frozen at start |

Not covered yet, by dependency: cost estimates on create/edit (F07.15); assessment projection jobs and
rank eligibility (F07.16, #247); directory/phone identity matching on add (F07.22); court-in-use checks
on removal (match schema); the offline start reservation (#246); public join-request submission (#248).
