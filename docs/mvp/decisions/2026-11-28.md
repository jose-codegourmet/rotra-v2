### D-2026-11-28-01 — The public session page moves to the Player app
- **Decision status:** approved (owner, November 28, 2026: "there is a flow users dont like · the public page for the session is at the queue app · is there a way we move it to player app · so it doesnt have to go to new tab on their phones?", then "Move it to Player", and each option below picked from lettered choices).
- **Implementation status:** built: merged to main in PR #1204, checked with `make check`. The merge did not record a browser check or a real-mode run against a database.
- **Ticket:** none (done straight from the owner's request).
- **Roadmap:** MVP — [Queue](../workstreams/queue.md), [Player Information](../workstreams/player.md)
- **Decision:**
  - **Where.** The public session page (Q-PUBLIC-*) is served by the Player app at the same path, `/s/[slug]`. It is still part of the Queue product: screen IDs, screen docs and business rules stay under Queue.
  - **Old links.** Queue's `/s/[slug]` stays as a permanent redirect (308) to the paired Player origin, with the query kept (`?join`, `?tab`, `?invite`, `?transfer`), so links and QR codes already shared keep working. New session links, QR codes, share, invite and transfer links are built on the Player origin.
  - **Same tab.** Links to the session page from the Player app (Games, the session matches dialog, the match page) open in the same tab. On the visitor page, Open club page, Open ROTRA profile and My ROTRA profile open in the same tab too. Admin and the Queue Master's preview keep new tabs.
  - **Look.** Unchanged: the page keeps its own account bar and does not get the Player top bar, nav or bands. The mockup does not change. The Google deadline gate does not stop the page.
  - **Receipt.** The visitor's join-request receipt cookie (#248) is set by the Player app's `/api/public-sessions/[slug]/join-request`. A visitor whose request was pending on the Queue domain at the switch sees no request and can send it again.
  - **Shared package.** The page's containers move to a new workspace package, `@rotra/session-page` (no outside dependency). The Player page and the Queue operator preview (`/sessions/[sessionId]/public-page`) both render it, so the preview stays under the club's sign-in and looks the same. The preview keeps reading Queue's own `/api/public-sessions/[slug]` routes; the Player app's session APIs accept same-origin calls and, for the preview, the paired Queue origin.
- **Not in MVP / Out of scope:** the Go move (B-51, go-public-reads) still names the "Queue public session page"; it follows this decision when that track runs.
