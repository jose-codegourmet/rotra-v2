### D-2026-11-20-01 — Record games off: games are recorded as usual, but their wins don't count toward the leaderboards or win rate
- **Decision status:** approved (owner, November 20, 2026: “when games are not recorded they are still gonna have leaderboards, the games will still be recorded but the wins will not be counted for the ranking”; then, the same day: “the only difference is those wins wont be part of the recorded wins for leaderboard, it wont affect the winrate”; and keep the name “Record games”; answers the same day: leave them out of the skill rank, and don't count them toward the Provisional or leaderboard game counts; write the migration and test it locally only). The open items below are not decided.
- **Implementation status:** mockup only ([Queue log](../../mockup-changes/2026-11-20-queue-record-games-not-ranked.md), [Player log](../../mockup-changes/2026-11-20-player-not-ranked-games.md)). The mock app and real mode still run the November 18 behavior (#973, #975, #976). Database: migration `20261120000100_record_games_ranks_only` (written; applied to a local disposable database 2026-11-20 only; **not applied to the shared database**: owner sign-off needed); the services are not changed yet.
- **Ticket:** none yet.
- **Roadmap:** MVP — [Queue](../workstreams/queue.md), [Player](../workstreams/player.md)
- **Replaces:** the “Off means run only, keep nothing” line of [D-2026-11-18-06](2026-11-18.md#d-2026-11-18-06). The switch itself (session form, on by default, fixed after Start) is unchanged.
- **Decision:**
  - With **Record games** off, the session runs and records exactly like a recorded one: Match done takes a winner and score; the Leaderboard, Match History, standings, result slides, awards and Publish results all work; finishing updates player records; the games appear in each player's history in the Player app with the night's win or loss.
  - **The only difference:** those wins and losses are not part of the **Top annual / monthly / weekly** leaderboards' wins and do not affect the player's **win rate**. The Player app lists them with fun and partial games (“Fun, partial and not ranked”) with a **Not ranked** note.
  - They also don't move the shared skill rank, and they don't count toward the Provisional game count or the leaderboard game count (owner's answers: like fun games).
  - The switch keeps the name **Record games**; Off reads “Off · not ranked”, and the session shows a **Not ranked** chip.
- **Open:**
  - Whether a not-ranked session counts for “has played at this club before” and the award baselines (Most Improved / Off Day) (mockup: no change shown).
  - Database: migration `20261120000100_record_games_ranks_only` (written; applied to a local disposable database 2026-11-20 only; **not applied to the shared database**: owner sign-off needed) makes every completed decision need a winner again. Still to build in the services: finishing writes `player_match_facts` for these sessions, and the leaderboard, win-rate and rank reads skip facts from a session with `record_games = false`. Applying the migration to the shared database needs the owner's sign-off.
