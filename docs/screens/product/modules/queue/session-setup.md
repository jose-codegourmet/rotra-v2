## Q-SETUP — Create / edit preparation wizard

**Entry:** **Create session** (club header on the dashboard, the phone dock, the now card when nothing is planned, a calendar day) or **Edit preparation**. **Actor:** licensed club operator. **Connectivity:** saving requires internet.

Header: “Create session” or “Edit preparation”, “For CLUB. Saving needs an internet connection.” Back link: Home, or Back to preparation.

A numbered step bar shows **three pages** (Date, venue and courts · Formats, mode and minimum · Costs and review), each containing two titled sections, and **every page is clickable at any time**, so the operator can skip ahead (hint: “Tap any step to jump to it. Finished steps glow green.”). Step states:

| State | When | Presentation |
|---|---|---|
| Current | The open step | Accent top bar |
| Done | Visited and its required fields are valid; every step of a saved session counts as visited | Green top bar with a soft green glow and ✓ |
| Needs details | Visited but a required field is missing or invalid (e.g. Details without a title) | Amber top bar and “!” |
| Not visited | Not opened yet | Neutral, step number |

Each step button's accessible name says its state (“Step 1, Date, venue and courts, complete”). Skipping never bypasses validation: **Next** still checks the current step, and saving checks every step and opens the first one with an error.

Footer: **Cancel**/**Back** and **Next** on pages 1–2; on page 3, the primary **Create session** (or **Save changes** when editing). Only page 3 saves. Enter in a field on pages 1–2 acts as **Next** (it checks that page and focuses the first error); Enter on page 3 saves once. Hint on new sessions: “Only page 1 is required; the rest uses sensible defaults you can change later. Create session is on page 3.” Older six-step drafts open on the matching page.

**Repeats (new sessions only).** Under the times: **Repeats** — Does not repeat (default), Every week, Every 2 weeks, Every month (same date; the last day of shorter months) — and, when repeating, **Number of sessions** (− / count / +, 2–12, default 4). Saving creates one prepared session per free date (toast “4 sessions created · 1 clashing date skipped”) and opens the first.

**Clash guardrails.** Every date is checked against the club's other sessions (not invalid ones):
- **Venue clash** — another session at the same venue overlaps: “Venue clash: Banilad Sports Hub is already booked for Sunday Night Queue, 6:00 PM–9:00 PM”.
- **Time clash** — another session at a different venue overlaps (the club runs one session at a time): “Time clash: Sunday Night Queue runs 6:00 PM–9:00 PM at Banilad Sports Hub”.
A single session that clashes shows the message on step 1 and cannot continue or save (“… Pick another date or time.”). In a series, clashing dates are skipped and never created; if every date clashes the step shows “Every date clashes with another session. Change the start date, time or venue.” Editing a saved session checks it against the others the same way. The step bar shows step 1 as needing details while a clash blocks it.

**Venue picker dialog.** **Choose a venue** lists the club's saved venues (name, address, “₱350/h per court” or “No court fee set”), with a search field (“Venue name or area”) and **Edit** per venue. Typing a name that isn't saved offers **+ Add “NAME” as a new venue**; with an empty search there is **+ Add a new venue**. Picking a venue fills the venue and address and, when saved, its court fee and entrance fee (toast: “Lahug Covered Court · court fee ₱250/h and entrance ₱60 filled in”). Picker rows show “₱250/h per court · ₱60 entrance”. The **New venue / Edit venue** form has Venue name (required, unique: “You already have a venue with this name.”), Address (optional) Court fee per hour per court (optional, 0 or more) and Entrance fee per head (optional, 0 or more; “If this venue charges each player to get in.”); saving adds it to the club's venues and selects it for this session. Validation on step 1: “Choose where you are playing.”

**Date picker dialog.** Every date field is a button showing a calendar icon and the full date (“Tuesday, December 15, 2026”); there is no native date input. It opens **Choose a date**, a single-date picker with no ranges:

- A highlighted summary of the selected date (“Today” under it when applicable).
- Month name with previous/next; previous is disabled on the current month.
- A seven-column month grid. Today has an accent ring; the selected day is filled. Past days are disabled, except a past date already saved on the session. Days on which the club already has another session show a small dot, explained by a legend (“Your club already has a session”).
- **Today** jumps back to today. Arrow keys move by a day (←/→) or a week (↑/↓), crossing months; one day is in the tab order at a time.
- Footer **Cancel** (or Escape) leaves the date unchanged; **Set date** applies it. Focus returns to the date field.

On phones the dialog is a bottom sheet.

Footer actions: **Cancel** on step 1, otherwise **Back**; **Next**; on the last step **Create session** / **Save changes**, the only save (creating and editing alike). Save buttons are disabled offline.

Validation on Next and on save:

| Field | Message |
|---|---|

| Venue empty | “Add where you are playing.” |
| Expected players (empty roster) | “Enter how many players you expect.” — whole number, at least 1 |
| Minimum (set by you) | “Use a whole number, 0 or more.” |
| Court fee / entrance fee | See Q-FINANCIALS |

A step with errors shows “Fix the highlighted fields to continue.” On save, the wizard jumps to the first step that has an error.

Offline: “You're offline. You can fill this in, but it isn't saved until you reconnect. A draft can't be run offline.”

Success: opens Q-PREPARE with “Session created” or “Preparation saved”.

New-session defaults: tomorrow, 19:00–22:00, Court 1 and Court 2, Doubles on, Singles off, Fair, calculated minimum, expected players = the slot budget (courts × players per court) until you change it, shuttle plan from the first shuttlecock item.

**Clash links.** Every time or venue clash message in setup (the single-date notice and each skipped date in a repeating series) ends with **View it**, which opens a summary dialog of the clashing session (status chip, when, venue, courts, roster count) with **Back to setup** (the draft is untouched) and **Open live session / preparation / session record**.

### Date-and-time picker

Owner decisions, November 6 and November 8, 2026. Every time field (Starts, Ends, each court's planned start and end, and the same picker in Q-START, Q-SESSION-ADJUST and Q-ADD-COURT) is one pattern, top to bottom:

1. **Empty option** (only when the field has one, e.g. a court's planned start): a segmented control with the empty label (“Session start” / “Session end”) and **Set time**. The empty label is pressed when the value is empty, and the day and time rows are hidden. **Set time** takes the fallback (the session start or end) when it is valid, else the first valid time.
2. **Day buttons** (a segmented control labelled with the date, the day after the base date marked “· next day”), shown only when the field can fall on more than one day.
3. **Time field**: one input-styled button with a clock icon, the time (“7:00 PM”) and a chevron, full width of its column. Pressing it opens the **time dialog** (bottom sheet on a phone; named after the field, e.g. “Starts”): the time in large type, an **AM | PM** switch, **Hour** buttons (12, 1 … 11, six per row) and **Minute** buttons (:00 :15 :30 :45), then **Done**. Each press sets the value at once and the field behind updates; close with ×, Escape, the backdrop or Done. On a field that allows the next day (Ends) the dialog ends with an **Ends the next day** switch. When the picker was opened from another dialog (Add court, Edit Court N), closing it returns to that dialog.

Only valid times can be picked, in 15-minute steps: an hour with no valid time on the chosen day and half, a minute not valid at the chosen hour, and AM or PM with no valid time on that day are disabled buttons. An existing value off the grid (a court opened at 10:42 PM) keeps its minute (:42) as an extra button while it is the value. Changing the hour keeps the minute when that time is valid, else takes the hour's first valid minute; changing AM/PM keeps hour and minute when valid in the other half, else takes that half's first valid time. A day with no valid times has its button disabled; a field with no empty option and no valid times shows “No times left on this day” instead of the time row. Choosing another day keeps the clock time when it is valid there, else takes that day's first valid time. Court times are never before the session start, and end after their own start and not after the session end. The session date itself still uses the calendar above. An error marks the time field; a disabled field disables it and its day buttons. Controls are named “LABEL: day”, “LABEL: TIME. Change time” for the time field (the time dialog is titled LABEL) and “LABEL: mode” for the empty option. Before November 8 the time was one native list of up to 96 times.

## Q-START — Start review

**Start session** (in the sticky bar) is disabled when any roster player has no level, another session is active (“TITLE is already running. Your club can run one session at a time.”), the device is offline (“Starting needs an internet connection.”; start is online only, [D-2026-11-07-03](../../../../mvp/decisions.md#d-2026-11-07-03)), or the license has ended (“Your license has ended, so new sessions can't start.”).

**Late or other-day start (owner decision, November 6, 2026).** When now is after the planned end, or on another calendar day than the planned start, the dialog opens with a warning notice “This session was planned for 6:00–9:00 PM yesterday. Set a new end time to start.” (further away: “planned for Sat, Nov 1, 6:00–9:00 PM”) and a required **New end** picker (today and tomorrow, after now and at most 24 h ahead), pre-filled with now + the planned length rounded up to the next 15 minutes and focused. **Start session** stays disabled until the new end is after now. Success saves the new end; courts that follow the session end move with it. The success toast becomes “Session started · levels locked · ends at 9:30 PM” (or “ends tomorrow 1:00 AM”). Every pending join request is closed at Start, and the toast adds “· N join requests closed” when there were any ([D-2026-11-11-11](../../../../mvp/decisions.md#d-2026-11-11-11)).

The dialog “Start session?” lists Session, Courts, Formats, Mode, Minimum, and Roster (“N confirmed · M present”), then: “Every player's level locks now. Players you add later get a level when you add them, and it locks too.” Offline adds “Starting needs an internet connection.” and Start session is disabled. Actions **Back** and **Start session**.

Success opens Q-CONSOLE on the Session view with “Session started · levels locked”. No match starts automatically. An empty roster does not block the start.

## Acceptance examples

- Creating a session without internet cannot produce a functioning offline event.
- Downloading on one device does not mark another device ready.
- A different active session blocks Start, but not recovery of the existing session.
- Starting locks levels already assigned in preparation.
- A roster player without a level blocks Start until a level is chosen.
- Adding a player in preparation changes the calculated minimum.

### Individual court windows

Q-SETUP offers planned start and planned end for each labeled court. Empty values follow the session start and end. Validate that each window is within the session and ends after its start; a court time on the day after the session date is chosen with its day button and shown with “· next day”. The slot budget remains courts × players per court; expected players is an estimate input, not an admission limit. In preparation the full budget routes new additions to the waitlist by default and **Give slot anyway** remains available.
