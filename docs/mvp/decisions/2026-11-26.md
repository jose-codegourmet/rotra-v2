### D-2026-11-26-01 — Session done deducts the planned shuttle tubes from inventory
- **Decision status:** approved (owner, November 26, 2026: "this should deduct the items once the session is done", then chose planned tubes, stop at zero, and deduct when it syncs).
- **Implementation status:** written in the mock store and the real-mode finalization; not run against a database yet.
- **Ticket:** none.
- **Roadmap:** MVP — [Queue](../workstreams/queue.md)
- **Decision:** replaces "stock is not deducted automatically" (open since [D-2026-11-11-06](2026-11-11.md#d-2026-11-11-06)).
  - **Amount.** Each shuttle plan line in the session's cost estimate takes its planned tubes off that inventory item. Two lines for the same item both count. No UI change: the Session done sheet asks nothing new.
  - **Never below zero.** Stock stops at 0; planning more than is in stock never blocks Session done.
  - **Once.** The deduction is part of the step that finishes the Session (the one finalization per session), so a retry or a second device never deducts twice. Session done needs a connection, so an offline night is deducted when it is finished online.
  - **Skipped.** A removed inventory item, a session with no estimate, and an invalid session deduct nothing.
  - **Corrections** stay manual: the Queue Master uses − and + in Inventory when the night used a different amount.
- **Open:** a stock history (which session took what) is not recorded; the database design suggests an append-only adjustment table if it is wanted.
- **References:** [financials](../../business_logic/product/queue/modules/financials/README.md), [estimate flow](../../business_logic/product/queue/modules/financials/flow/estimate-session-costs.md), [database design](../../database_design/product/queue/modules/financials-inventory.md).

- **Decision status:** approved (owner artifact comment, November 26, 2026: "there should be settings and if there is a game it should be leaderboard ( back to session / incoming session ) profile"; then "maybe just PLAY and if about to start say READY", "remove settings if there is an active session and if the upcoming session is within the day", and, on the button style, "please go with the ready and start button" and "hey do the pixel design").
- **Implementation status:** not started (mockup only).
- **Ticket:** needed (see the mockup logs: [dock, Settings and session slot](../../mockup-changes/2026-11-26-player-dock-settings-session.md), [session button style](../../mockup-changes/2026-11-26-player-session-button-options.md)).
- **Roadmap:** MVP — [Player](../workstreams/player.md)
- **Amends:** [D-2026-11-19-13](2026-11-19.md#d-2026-11-19-13) (the dock and top bar gain a session slot and Settings).
- **Decision:**
  - **Main navigation, signed in** (top bar on wide screens, bottom dock on phones): **Leaderboard · session slot · My profile · Settings**. Visitors keep **Leaderboard · Sign in**.
  - **Session slot**, shown only when the player has a game: **Play** while a session they're in is happening now; **Ready** when the next session they're in is today; **Next up** when it is a later day. It opens that session's page (`/queue/s/<slug>`), like the Home cards. On the dock it is the highlighted middle item.
  - **Pixel button.** The session button is the pixel START-style button (option 5 of the options round): ink outline with stepped corners, Silkscreen type, the word alone with no icon, a press that pushes the face down, a pixel-step shine while live. Brand-sprite tokens `--px-*`, the same in both themes; built in CSS and inline SVG. The wide-screen top bar uses the same pixel button (14 px type) in place of the green pill. Options 1–4 and the Prototype "Session button style" switch are removed. Reduced motion turns every animation off.
  - **Settings page** (P-SETTINGS, `/player/settings`, signed in only). It only gathers what already exists: Account (Edit profile, Privacy and contact, Verification), This device (Dark mode switch) and Sign out. No new setting.
  - **Settings leaves the nav** while a session is happening now, or when the incoming session is today (dock: Leaderboard · session · My profile). It stays reachable from a new **Settings** button on My profile's Your account card.
  - Prototype panel: a "Your sessions" switch (Current session · Incoming today · Incoming in a few days · No session) drives the dock and Home's cards.
- **Open:** whether **Next up** should only show within a time window (today, or the next 24 hours) instead of for the soonest session at any distance. The mockup shows it for the soonest one.
