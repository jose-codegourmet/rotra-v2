### D-2026-11-20-01 — Record games off: games are recorded as usual, but their wins don't count toward the leaderboards or win rate
- **Decision status:** approved (owner, November 20, 2026: “when games are not recorded they are still gonna have leaderboards, the games will still be recorded but the wins will not be counted for the ranking”; then, the same day: “the only difference is those wins wont be part of the recorded wins for leaderboard, it wont affect the winrate”; and keep the name “Record games”). The open items below are not decided.
- **Implementation status:** mockup only ([Queue log](../../mockup-changes/2026-11-20-queue-record-games-not-ranked.md), [Player log](../../mockup-changes/2026-11-20-player-not-ranked-games.md)). The mock app and real mode still run the November 18 behavior (#973, #975, #976).
- **Ticket:** none yet.
- **Roadmap:** MVP — [Queue](../workstreams/queue.md), [Player](../workstreams/player.md)
- **Replaces:** the “Off means run only, keep nothing” line of [D-2026-11-18-06](2026-11-18.md#d-2026-11-18-06). The switch itself (session form, on by default, fixed after Start) is unchanged.
- **Decision:**
  - With **Record games** off, the session runs and records exactly like a recorded one: Match done takes a winner and score; the Leaderboard, Match History, standings, result slides, awards and Publish results all work; finishing updates player records; the games appear in each player's history in the Player app with the night's win or loss.
  - **The only difference:** those wins and losses are not part of the **Top annual / monthly / weekly** leaderboards' wins and do not affect the player's **win rate**. The Player app lists them with fun and partial games (“Fun, partial and not ranked”) with a **Not ranked** note.
  - They also don't move the shared rank (the owner's first message: “the wins will not be counted for the ranking”).
  - The switch keeps the name **Record games**; Off reads “Off · not ranked”, and the session shows a **Not ranked** chip.
- **Open:**
  - Whether these games count toward the rank's Provisional game count and the leaderboard eligibility count (mockup: no, like fun games).
  - Whether a not-ranked session counts for “has played at this club before” and the award baselines (Most Improved / Off Day) (mockup: no change shown).
  - Database: Match done on an unrecorded session must store a winner again, so `match_decisions_record_games_guard` (migration `20261119000100_session_record_games`, already on the shared database) needs a new migration; finishing writes `player_match_facts` again, and the leaderboard, win-rate and rank reads skip facts from a session with `record_games = false`. Not written; ask before the migration.
