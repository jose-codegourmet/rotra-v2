## Phase 2: Core

- [x] **2.1** Password hashing (argon2id, bcrypt verify, rehash) in `apps/api/internal/auth/password`: Params and PHC hashes, bcrypt `$2a/$2b/$2y` verify, rehash flag, `Hasher` with a concurrency cap and a dummy hash, `ROTRA_AUTH_HASH_CONCURRENCY`

## Phase 3: Flows

- [x] **3.1** Club sign-in (username): `apps/api/internal/auth/signin` (`POST /api/auth/sign-in`, `GET /api/auth/session`, `POST /api/auth/sign-out`, `POST /api/auth/refresh`, shared with 3.2 and 3.3); wired in `cmd/api` with the `ROTRA_AUTH_*` tuning
- [x] **3.2** Player sign-in (email) and claim: email sign-in in `signin`; the claim in `apps/api/internal/auth/claim` (`GET` and `POST /api/claim/{token}`, player app only), with `internal/player/{fields,identity,profile}` (phone rule, RTR ID and phone linking, profile details `Parse`/`Save` for the later `/api/me` track) and `password.Validate`; golden from the real Route Handlers (`capture-claim.test.mjs`); wired in `cmd/api` beside the sign-in routes
- [x] **3.3** Admin sign-in (`denied` issues no session)
- [x] **3.4** Admin-reviewed recovery link: `apps/api/internal/auth/recovery` (service functions `Submit`, `ReadRequests`, `Review`, `Reset`; public routes `POST /api/auth/password-reset` and `POST /api/auth/reset-password`, player app only, wired in `cmd/api` beside the claim routes); golden from the real Route Handlers (`capture-recovery.test.mjs`). The Admin list and review HTTP routes are not registered: they belong to go-writes-admin-player (track 8), which must authenticate the Admin and call `ReadRequests` and `Review`
- [x] **3.5** Queue device enrollment (acceptance met by 3.1 and 2.3): already met by 3.1 and 2.3, nothing new built. Asserted by tests: enrolls with a cleaned label and the session carries the device (`signin` `TestClubDeviceEnrollment/enrolls`), the `device_enrolled` event (same test; `session` `issue_test.go`), another club's device is 404 and a revoked one 403 with no session left behind (`TestClubDeviceEnrollment/another club's device...`), revoking a device revokes its sessions and refuses its sign-in (`session` `TestRevokeDevice`). Not part of enrollment and not done here: refusing replayed commands from a revoked device (go-writes-queue, track 9), the revoke dialog (mockup first, BL-7), the device list endpoints (4.2)
