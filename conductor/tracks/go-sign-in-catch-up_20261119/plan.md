## Phase 2: Google sign-in (build; owner, 2026-11-23)

- [x] **2.1** Characterize the seven Google routes on `main` with the provider stubbed (goldens, as the register capture does): every route answers 404 while the flag is off, then the flag-on cases per route. Done 2026-11-23: groups `google` (flag off, request checks) and `googleflow` (58 cases: outcome, link, unclaimed, claim and register with Google, password reset's `signsInWithGoogle`), captured from the TypeScript with only the held Google account and the result cookie stubbed. Three Go differences found and fixed (email confirmed at once, account revision 1, signed-in result needs Google connected)
- [x] **2.2a** Direct Google OIDC client in Go (no new dependency): state, PKCE and nonce kept in short-lived httpOnly cookies, ID token checked with the standard library, `player_google_sign_in` flag read. `internal/auth/google/oidc.go`: code flow with state, PKCE S256 and nonce; the ID token is checked (RS256 against Google's published keys, issuer, audience, expiry, nonce, verified email) with the standard library only. Tested against a fake Google endpoint; **never run against real Google** (no OAuth client exists)
- [x] **2.2b** `/api/auth/google/start`, `/callback`, `/outcome`, `/link`, `/unclaimed`: linking rules decided from ROTRA's own record, Google email as the identity key. `/api/auth/google/start`, `callback`, `outcome` (GET and POST), `link`, `unclaimed` (`google.go`, `decide.go`, `identities.go`), the held account as a signed cookie, the session issued only after ROTRA's record says Google is connected, and the identity cards of D-2026-11-16-04
- [x] **2.2c** `/api/claim/{token}/google` and `/api/register/{clubId}/google` (shared-entry RTR ID adoption); BL-14 preset email in `GET /api/claim/{token}`. `POST /api/claim/{token}/google` (`claim.go`) and `POST /api/register/{clubId}/google` (`internal/auth/register/google.go`), both through the claim's own transaction with a login that has no password and Google recorded in the same transaction; BL-14 fixed (`GET /api/claim/{token}` preset email prefers the shared entry's); password reset tells a Google-only account to use Google (`signsInWithGoogle`)
- [x] **2.3** Google session and deadline rules in Go and in the apps' pass check (`startedWithOAuth`, `googleRequiredFor`, `/connect-google` redirect). No Google session flag is needed: Go issues a session only after ROTRA's record says Google is connected, so the `startedWithOAuth` rule holds by construction. The deadline gate already ran on Go's Player routes (`signedin.GoogleRequired`); now Go also keeps the Player proxy's `rotra-player-google-gate` hint in step (`signin.Deps.PlayerSession`, `cmd/api`) and `apps/player/src/proxy.ts` redirects to `/connect-google` in Go mode
- [x] **2.4** Add this track's `/api/*` prefixes to the `ROTRA_GO_MOVED_AREAS` list (local now; the beta project gets the full list in staging-verification). The Google routes sit under `/api/auth` and `/api/claim`, already in the list. `/api/register` cannot be listed as a prefix (the Admin link's `POST /api/register` and `/api/register/google` are not in Go), so the exact-path entry `=/api/register/*/google` (see packages/api-proxy/AGENTS.md) moves Google registration; password `/api/register/{clubId}` cannot be separated from `/api/register/google` and stays TypeScript (BL-19)
