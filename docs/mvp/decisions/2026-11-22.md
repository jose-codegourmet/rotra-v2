### D-2026-11-22-01 — Trusted club hosts and session host display
- **Decision status:** approved (owner, epic [#1002](https://github.com/jose-codegourmet/rotra-v2/issues/1002), November 22, 2026).
- **Implementation status:** in progress — #1003 (Club settings › Trusted hosts), #1004 (session setup › Hosts with auto-registration) and #1005 (change hosts before and during the session) are in the mockup, the mock app and real mode (services + Route Handlers); migrations `20261122000100_club_trusted_hosts` and `20261122000200_session_hosts` are written and checked on a local disposable database only, **not applied to the shared database** (owner sign-off needed). The public Hosts section, the Host badge and host snapshots follow in the later tickets of the epic.
- **Ticket:** [#1003](https://github.com/jose-codegourmet/rotra-v2/issues/1003), [#1004](https://github.com/jose-codegourmet/rotra-v2/issues/1004), [#1005](https://github.com/jose-codegourmet/rotra-v2/issues/1005) (epic #1002); later tickets of the epic update this line.
- **Roadmap:** MVP — [Queue](../workstreams/queue.md), [Player](../workstreams/player.md)
- **Decision:**
  - **Hosting is informational, not authorization.** The club account (club credentials) stays the only way to operate the Queue app. No new roles, permissions or logins.
  - **Trusted hosts.** The club keeps a **trusted-host list** drawn from its saved players, in **Club settings › Trusted hosts**: add from saved players not on it, remove with a confirmation. Saved players can be trusted hosts without a ROTRA account (guests and unclaimed players). The list is separate from saved-player membership and from Queue permissions: adding or removing changes only the list.
  - **Removing a trusted host** removes their current Host badge and their place first in the host picker, but never their saved-player membership nor historical session host records. Past sessions keep host snapshots.
  - **Session hosts.** A Queue Session's **Hosts** section is optional (zero hosts is valid). Session creation can select several trusted hosts. Assigning a host auto-registers that person as a playing participant (roster), using one capacity slot (two hosts = 2/16), without duplicating an existing registration; capacity follows the existing roster and waitlist rules when full.
  - **Another saved player as host.** The session creator may pick a non-trusted saved player as host with a plus picker; a confirmation says this permanently adds them to the club's trusted-host list. Already selected hosts can't be picked twice. Picker order: trusted hosts first, then other saved players.
  - **During a session** hosts can be changed. Removing a host designation never removes their player registration; withdrawing as a player never removes the host designation. The existing queue controls handle withdrawal, rejoin and the waitlist.
  - **Host badge.** When a trusted host is linked to a ROTRA player account, their public player profile's Clubs section shows a **Host** badge for each club where they are currently trusted.
  - **Public queue page:** a compact **Hosts** section, then Players, then Waitlisted. A host who plays appears in both Hosts and Players but counts once toward capacity.
  - **Words:** *Trusted host* (code `trustedHost`) and *Host* (code `sessionHost`) in [product terms](../../product-terms.md#4-players-identity-and-presence). UI copy: "Trusted hosts" (Club settings), "Hosts" (session setup, management and public page), badge "Host".
- **Data model (agreed shape):**
  - `club_trusted_hosts` (#1003, Prisma `ClubTrustedHost` in `schema/queue/club-host.prisma`): `id`, `club_id`, `club_player_id` (scoped FK to `club_players`, RESTRICT), `added_at`, `removed_at` (null = current; soft, so history stays), `created_at` / `updated_at` / `revision`. One current row per `(club_id, club_player_id)` (partial unique index where `removed_at` is null). RLS on, no anon/authenticated grants.
  - `session_hosts` (#1004, same file): `id`, `club_id`, `session_id` (FK to `queue_sessions`), `club_player_id` (FK, RESTRICT), `assigned_at`, `removed_at` (null = current host), timestamps. One current row per `(session_id, club_player_id)`.
  - Snapshot columns on `session_hosts` (#1008), e.g. the host display name at assignment, frozen at finalization, so finished sessions show their hosts after a trusted-host removal, a saved-player removal or identity linking (`linked_to_club_player_id`).
  - Mock mode: the mock store keeps `clubTrustedHosts` (current and removed rows); the trusted-host hooks are `useTrustedHosts`, `useAddTrustedHost`, `useRemoveTrustedHost` (`@rotra/data/trusted-host/*`).
- **Settled in #1003:** a trusted host whose saved player the club deleted, or moved into another saved player (Same person), drops off the list read; the row stays as history. Toasts: "NAME added to trusted hosts", "NAME removed from trusted hosts". Club settings stays online only.
- **Settled in #1004 (session setup › Hosts):**
  - The Hosts field sits on setup page 1 › Courts, under the slot budget, with a **Hosts** row in the review. The setup payload carries `hostClubPlayerIds` (the full list after the save; left out = unchanged); every date of a repeating series gets the same hosts.
  - The trusted-host confirmation adds the saved player to the trusted-host list **at confirm time** (not at save), so it stays even if the setup is abandoned, as the copy says (“permanently adds”). A save refuses a new host who is not a current trusted host; hosts already on the session stay even if later removed from the list.
  - **Capacity:** there is no host-specific rule, so the existing preparation rule applies: new hosts take open slots in the order picked, and the rest go on the end of the waitlist (never past the budget; Add anyway stays a Queue Master choice in Add player). The setup warns before saving. Already registered (slot or waitlist, or another saved record of the same ROTRA player in the mock) = no new registration.
  - A host is registered with their saved level (mock: the saved player's level; real: the latest club assessment) or, without one, with no level (set in Roster and levels before Start; a waitlisted host without a level is skipped by automatic fills, as today).
  - Removing a host in Edit preparation ends only the host row. Deleting a prepared session deletes its host rows.
  - Toasts: the save adds “· N hosts registered” / “· N hosts waitlisted”; the confirmation toasts “NAME added to trusted hosts”.
  - Code: `packages/data/src/session-host/` (`useSessionHosts`, `hostPlacement`, mock write `assignSessionHosts`), `packages/db/src/queue/session-hosts.ts`, `GET /api/sessions/[sessionId]/hosts`, `@rotra/ui` `SetupHostsSection` and `HostPickerSheet`.
- **Settled in #1005 (change hosts before and during the session):**
  - A compact **Hosts** card (title “Hosts · N”, **Add host**, a row per host with a Host chip and **Remove**) sits in the Overview of Q-PREPARE, prepared and live (the live console's Settings opens the same page). Add host reuses the setup's Add host sheet, trusted-host confirmation included; new hosts follow the #1004 rule (a slot while one is open, otherwise the end of the waitlist; no second registration for someone already in).
  - **Remove** ends only the host row (`session_hosts.removed_at`). The player's slot or waitlist place and their trusted-host status stay. Withdrawing, sitting out, stepping down and no-show never touch `session_hosts` (checked in the mock store and the real services); a withdrawn host stays a host and the card says “Not on the roster”.
  - **Live, levels are locked:** a host who is not on the roster or waitlist and has no saved level is refused (“NAME has no saved level. Add them as a player with a level first, then add them as a host.”) rather than placed without a level. A host added to a live slot is present and level-locked, like any player admitted during play; a full live session sends them to the waitlist.
  - **Online only** (it changes the roster), like the setup save. No schema change: `session_hosts.removed_at` already carries the history. Toasts: “NAME added as a host · 1 host registered / waitlisted”, “NAME removed as a host”.
  - **Waitlisted host with no level** (before Start): skipped by the automatic fills in both modes (the mock now matches real mode; it used to throw). A direct “Give slot” still asks for a level first.
  - Code: `addSessionHost` / `removeSessionHost` (`@rotra/data/session-host/fetchers`, hooks `useAddSessionHost`, `useRemoveSessionHost`), `packages/db/src/queue/session-hosts.ts` (`addSessionHost`, `removeSessionHost`), `POST /api/sessions/[sessionId]/hosts` and `DELETE /api/sessions/[sessionId]/hosts/[clubPlayerId]`, `@rotra/ui` `SessionHostsCard`, container `SessionHosts`.
- **Not in MVP / Out of scope:** Facebook share-post changes; a personal player-account host login or host permissions; new permissions or roles.
