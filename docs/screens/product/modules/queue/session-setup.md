**Surfaces:** `Q-SETUP`, `Q-PREPARE`, `Q-DOWNLOAD`, `Q-START`.

**Sources:** [sessions](../../../../business_logic/product/queue/modules/sessions/README.md), [offline rules](../../../../business_logic/product/queue/modules/offline/README.md), [financials](../../../../business_logic/product/queue/modules/financials/README.md). **Reference:** [ROTRA Queue prototype](../../../../../apps/mockup/queue-app/rotra-queue.html).

## Q-SETUP — Create / edit preparation wizard

**Entry:** **Create session** (club header on the dashboard, the phone dock, the now card when nothing is planned, a calendar day) or **Edit preparation**. **Actor:** licensed club operator. **Connectivity:** saving requires internet.

Header: “Create session” or “Edit preparation”, “For CLUB. Saving needs an internet connection.” Back link: Home, or Back to preparation.

A numbered step bar shows **three pages** (Date, venue and courts · Formats, mode and minimum · Costs and review), each containing two titled sections, and **every page is clickable at any time**, so the operator can skip ahead (hint: “Tap any step to jump to it. Finished steps glow green.”). Step states:

| State | When | Presentation |
|---|---|---|
| Current | The open step | Accent top bar |
| Done | Visited and its required fields are valid; every step of a saved session counts as visited | Green top bar with a soft green glow and ✓ |
| Needs details | Visited but a required field is missing or invalid (e.g. Details without a title) | Amber top bar and “!” |
| Not visited | Not opened yet | Neutral, step number |

Each step button's accessible name says its state (“Step 1, Date, venue and courts, complete”). Skipping never bypasses validation: **Next** still checks the current step, and saving checks every step and opens the first one with an error.

Footer: **Cancel**/**Back** and **Next** on pages 1–2; on page 3, the primary **Create session** (or **Save changes** when editing). Only page 3 saves. Enter in a field on pages 1–2 acts as **Next** (it checks that page and focuses the first error); Enter on page 3 saves once. Hint on new sessions: “Only page 1 is required; the rest uses sensible defaults you can change later. Create session is on page 3.” Older six-step drafts open on the matching page.

### Date-and-time picker

Owner decisions, November 6 and November 8, 2026. Every time field (Starts, Ends, each court's planned start and end, and the same picker in Q-START, Q-SESSION-ADJUST and Q-ADD-COURT) is one pattern, top to bottom:

1. **Empty option** (only when the field has one, e.g. a court's planned start): a segmented control with the empty label (“Session start” / “Session end”) and **Set time**. The empty label is pressed when the value is empty, and the day and time rows are hidden. **Set time** takes the fallback (the session start or end) when it is valid, else the first valid time.
2. **Day buttons** (a segmented control labelled with the date, the day after the base date marked “· next day”), shown only when the field can fall on more than one day.
3. **Time field**: one input-styled button with a clock icon, the time (“7:00 PM”) and a chevron, full width of its column. Pressing it opens the **time dialog** (bottom sheet on a phone; named after the field, e.g. “Starts”): the time in large type, an **AM | PM** switch, **Hour** buttons (12, 1 … 11, six per row) and **Minute** buttons (:00 :15 :30 :45), then **Done**. Each press sets the value at once and the field behind updates; close with ×, Escape, the backdrop or Done. On a field that allows the next day (Ends) the dialog ends with an **Ends the next day** switch. When the picker was opened from another dialog (Add court, Edit Court N), closing it returns to that dialog.

Only valid times can be picked, in 15-minute steps: an hour with no valid time on the chosen day and half, a minute not valid at the chosen hour, and AM or PM with no valid time on that day are disabled buttons. An existing value off the grid (a court opened at 10:42 PM) keeps its minute (:42) as an extra button while it is the value. Changing the hour keeps the minute when that time is valid, else takes the hour's first valid minute; changing AM/PM keeps hour and minute when valid in the other half, else takes that half's first valid time. A day with no valid times has its button disabled; a field with no empty option and no valid times shows “No times left on this day” instead of the time row. Choosing another day keeps the clock time when it is valid there, else takes that day's first valid time. Court times are never before the session start, and end after their own start and not after the session end. The session date itself still uses the calendar above. An error marks all three dropdowns; a disabled field disables them all. Controls are named “LABEL: day”, “LABEL: hour”, “LABEL: minute” and “LABEL: AM or PM” (and “LABEL: mode” for the empty option). Before November 8 the time was one native list of up to 96 times.

## Q-DOWNLOAD — Device readiness

Card **This device** with a chip: **Not downloaded on this device**, **Downloading…** (warning), or **Ready on this device** (success).

Copy: “Download the session so this device can keep running it if the venue's internet drops. A download on one device doesn't prepare any other device.” Button **Download for offline use**, or **Update download** when ready; disabled while downloading and offline (“Downloading needs an internet connection.”). ## Q-START — Start review

**Start session** (in the sticky bar) is disabled when any roster player has no level, another session is active (“TITLE is already running. Your club can run one session at a time.”), the device is offline (start is online only, [D-2026-11-07-03](../../../../mvp/decisions.md#d-2026-11-07-03)), or the license has ended (“Your license has ended, so new sessions can't start.”).

**Late or other-day start (owner decision, November 6, 2026).** When now is after the planned end, or on another calendar day than the planned start, the dialog opens with a warning notice “This session was planned for 6:00–9:00 PM yesterday. Set a new end time to start.” (further away: “planned for Sat, Nov 1, 6:00–9:00 PM”) and a required **New end** picker (today and tomorrow, after now and at most 24 h ahead), pre-filled with now + the planned length rounded up to the next 15 minutes and focused. **Start session** stays disabled until the new end is after now. Success saves the new end; courts that follow the session end move with it. The success toast becomes “Session started · levels locked · ends at 9:30 PM” (or “ends tomorrow 1:00 AM”).

The dialog “Start session?” lists Session, Courts, Formats, Mode, Minimum, and Roster (“N confirmed · M present”), then: “Every player's level locks now. Players you add later get a level when you add them, and it locks too.” Offline adds “Starting on this device while offline. It syncs when you reconnect.” Actions **Back** and **Start session**.

> MVP: offline start removed by [D-2026-11-07-03](../../../../mvp/decisions.md#d-2026-11-07-03); prototype copy update pending a mockup change (the sticky-bar and Q-START no-download reasons and the offline start line above).

Success opens Q-CONSOLE on the Session view with “Session started · levels locked”. No match starts automatically. An empty roster does not block the start.

## Acceptance examples

- Creating a session without internet cannot produce a functioning offline event.
- Downloading on one device does not mark another device ready.
- A different active session blocks Start, but not recovery of the existing session.
- Starting locks levels already assigned in preparation.
- A roster player without a level blocks Start until a level is chosen.
- Adding a player in preparation changes the calculated minimum.

### Individual court windows

Q-SETUP offers planned start and planned end for each labeled court. Empty values follow the session start and end. Validate that each window is within the session and ends after its start; a court time on the day after the session date is chosen with its day button and shown with “· next day”. The slot budget remains courts × players per court; expected players is an estimate input, not an admission limit. In preparation the full budget routes new additions to the waitlist by default and **Give slot anyway** remains available.
